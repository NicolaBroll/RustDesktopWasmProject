# Packaging

| Command | Output (in `target/`) |
| --- | --- |
| `make appimage` | `appimage/BinariGit-<version>-x86_64.AppImage` + its `.zsync` + `appimage/SHA256SUMS.txt` |
| `make windows` | `windows/BinariGit-<version>-x86_64-windows.zip` + `windows/BinariGit-<version>-x86_64.msi` + `windows/SHA256SUMS.txt` |

The version comes from `[workspace.package]` in the root `Cargo.toml`. No package bundles
git: BinariGit runs the system `git` for every operation.

## Linux AppImage (`packaging/appimage.sh`)

Build requirements: Rust, `curl`, `sha256sum`. The script builds `apps/project` in release,
assembles `target/appimage/BinariGit.AppDir` (`AppRun`, `binarigit.desktop`, icon) and runs
appimagetool. Both tools are pinned and downloaded into `target/packaging-cache/`; a file is used
only after its sha256 matches the one in the script (the digests GitHub publishes for the assets):

| Tool | Version | sha256 |
| --- | --- | --- |
| [appimagetool](https://github.com/AppImage/appimagetool/releases/tag/1.9.1) `appimagetool-x86_64.AppImage` | 1.9.1 | `ed4ce84f0d9caff66f50bcca6ff6f35aae54ce8135408b3fa33abfc3cb384eb0` |
| [type2-runtime](https://github.com/AppImage/type2-runtime/releases/tag/20251108) `runtime-x86_64` | 20251108 | `2fca8b443c92510f1483a883f60061ad09b46b978b2631c807cd873a47ec260d` |

The AppImage embeds the update information
`gh-releases-zsync|<owner>|<repo>|latest|BinariGit-*-x86_64.AppImage.zsync` (repo from
`GITHUB_REPOSITORY`, `NicolaBroll/RustDesktopWasmProject` outside CI), and appimagetool writes the
`.zsync` next to it. The Release publishes both, so AppImageUpdate, Gear Lever or AppImageLauncher
update an installed AppImage to the latest (non-prerelease) Release, downloading only the changed
blocks. Check with `objcopy -O binary --only-section=.upd_info <AppImage> /dev/stdout`.

The runtime is passed with `--runtime-file`, so appimagetool does not fetch the unpinned
"continuous" one. appimagetool runs with `APPIMAGE_EXTRACT_AND_RUN=1` (no FUSE needed).

Runtime requirements on the user's machine:

- **glibc 2.35 or newer** (Ubuntu 22.04, Debian 12, Fedora 36 and later): the binary links only
  `libc`, `libm`, `libgcc_s` and its highest symbol version is `GLIBC_2.35`. Check after a build
  with `objdump -T target/release/project | grep -o 'GLIBC_[0-9.]*' | sort -uV | tail -1`;
  building on a host with a newer glibc can raise it.
- `git` on `PATH`.
- Libraries loaded at runtime (`dlopen`) from the host, not bundled, as usual for AppImages:
  OpenGL (`libgl1`), `libxkbcommon-x11-0`, `libxcursor1`, `libxi6` on X11 (`libwayland-client0`
  on Wayland). A desktop install has them; a minimal Ubuntu 22.04/24.04 container needs exactly
  `git libgl1 libxkbcommon-x11-0 libxcursor1 libxi6`.
- FUSE 2/3 to mount the AppImage; without it: `APPIMAGE_EXTRACT_AND_RUN=1 ./BinariGit-*.AppImage`
  or `./BinariGit-*.AppImage --appimage-extract-and-run`.

Smoke test in a clean container (Docker):

```sh
apt-get install -y --no-install-recommends git libgl1 libxkbcommon-x11-0 libxcursor1 libxi6 \
    xvfb xauth imagemagick
APPIMAGE_EXTRACT_AND_RUN=1 xvfb-run -a -s '-screen 0 1280x800x24' sh -c \
    './BinariGit-*.AppImage <repo> & sleep 10; import -window root shot.png; kill $!'
```

## Windows zip and MSI (`packaging/windows.sh`)

Cross-compiled from Linux for `x86_64-pc-windows-gnu`. Build requirements: the rustup target
(added by the script if missing) and `gcc-mingw-w64-x86-64`, `binutils-mingw-w64-x86-64`
(`windres`, for the icon), `zip` and `wixl` (from `msitools`, for the MSI) — installed by
`.devcontainer/post-create.sh`.
`apps/project/build.rs` embeds `assets/icon.ico` (regenerated by `assets/render.sh`) with
`windres`; on the MSVC target it skips the icon with a warning.

The zip holds `BinariGit/BinariGit.exe` and `BinariGit/README.txt`. The exe imports only system
DLLs (OpenGL32, user32, ...). Requirements on the user's machine: Windows 10 or later, OpenGL 2+
drivers, [Git for Windows](https://git-scm.com/download/win) with `git.exe` on `PATH`. The exe is
not signed (SmartScreen warns on first start); signing comes later (S43).

The MSI (`packaging/binarigit.wxs`, compiled by `wixl`) holds the same files as the zip:

- **Per-user install**: no administrator rights and no UAC prompt; the files go in
  `%LOCALAPPDATA%\Programs\BinariGit`, a shortcut in the user's Start menu, the icon in
  "Installed apps", where it is uninstalled (no Modify or Repair). Two `HKCU\Software\BinariGit`
  values serve as the key paths Windows Installer needs for per-user files; they go away with the
  uninstall. The app's own settings (eframe storage) are not touched by the uninstall.
- **No dialogs**: double-clicking it shows only Windows Installer's progress bar.
  `msiexec /i BinariGit-<version>-x86_64.msi /qn` installs silently, `msiexec /x <same file>`
  removes it.
- **Upgrades**: a newer MSI replaces the installed version (same `UpgradeCode`, `MajorUpgrade`);
  an older one is refused. The MSI version is the numeric part of the crate version (`0.5.0-rc.1`
  → `0.5.0`), so two builds of the same version replace each other.
- Inspect a build on Linux with `msiinfo export <msi> File` (also `Directory`, `Shortcut`,
  `Registry`, `Property`) and `msiinfo suminfo <msi>`.

On Windows, cancelling a git command (fetch, pull, ...) stops `git.exe` with `TerminateProcess`:
its children (ssh, helpers) may outlive it and its lock files (e.g. `index.lock`) may remain.

## Verifying a download

Put `SHA256SUMS.txt` next to the file and run `sha256sum -c SHA256SUMS.txt` (Linux), or on
Windows `Get-FileHash BinariGit-<version>-x86_64-windows.zip` (or the `.msi`) in PowerShell and compare with the
line in `SHA256SUMS.txt`.

## GitHub Actions

`.github/workflows/package.yml` runs both builds on Ubuntu (the AppImage on `ubuntu-22.04`, for
the glibc baseline; Windows cross-compiled) on every push to `master`, on `v*` tags, on pull requests that touch `packaging/`, the
workflow or `apps/project/build.rs`, and by hand ("Run workflow" in the Actions tab, any branch,
once the workflow is on `master`). The packages are artifacts of the run (`appimage`,
`windows`, kept 90 days). On a `v*` tag a GitHub Release is created with the AppImage, its `.zsync`, the zip, the MSI and
one `SHA256SUMS.txt` for both. Artifacts are downloaded as zip files, which drop the executable
bit: after extracting, `chmod +x BinariGit-*.AppImage` (same for a download from the Release).
